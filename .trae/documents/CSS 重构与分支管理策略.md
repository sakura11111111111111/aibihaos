# CSS 重构与分支管理策略

## 1. CSS 模块化重构方案

目前的 `style.css` 文件已经超过 500 行，包含了从基础样式、侧边栏、编辑器、弹窗到各个视图的所有样式。这种“大杂烩”模式是导致样式冲突和维护困难的根源。

**我建议采用“按功能拆分”的策略，将 CSS 拆解为多个独立文件：**

1.  **`base.css`**: 重置样式、全局变量、通用工具类（如 `.tooltip`）。
2.  **`layout.css`**: 侧边栏、主内容区容器、Split.js 分割条等宏观布局。
3.  **`components.css`**: 通用组件样式（按钮、输入框、徽章）。
4.  **`views/editor.css`**: 编辑器页面专用样式（Quill 定制、预览块）。
5.  **`views/todo.css`**: 待办事项页面专用样式（两栏布局、任务列表）。
6.  **`views/all-notes.css`**: 所有笔记页面专用样式（三栏布局、分类树）。

**实施方式**：
在 `src/main.js` 中统一引入，或者在各自的 JS 视图文件中按需引入（Vite 支持这种方式）。

## 2. Git 分支管理策略 (防止意外损坏)

为了避免“改了一个页面坏了另一个页面”的情况直接影响主干，建议严格执行以下分支策略：

1.  **主分支保护 (`master`)**:
    *   **原则**: 永远保持可发布、无 Bug 的状态。
    *   **操作**: **严禁直接在 master 上修改代码**。

2.  **功能分支开发 (`feature/xxx`)**:
    *   **原则**: 每个新功能（如“待办事项”、“样式重构”）都必须新建一个分支。
    *   **命名规范**: `feature/todo-list`, `refactor/css-split`。
    *   **操作**: 开发完成后，必须在本地测试无误，才能合并回 master。

3.  **里程碑标签 (`tag`)**:
    *   **原则**: 每当完成一个大的稳定版本，打一个 Tag。
    *   **操作**: `git tag v1.0.0`。

## 3. 接下来必须完成的操作 (Checklist)

1.  **新建重构分支**: `git checkout -b refactor/css-modularization`
2.  **执行 CSS 拆分**: 按照上述方案，创建 `src/styles/` 目录并拆分文件。
3.  **修复待办事项功能**: 在样式重构完成后，在一个新的功能分支 `feature/todo-list-v2` 上重新实现待办事项功能（这次有了独立的 CSS，就不会污染全局了）。
